## What was measured

Users are partitioned by **primary topic** (argmax of the interest vector).
An oracle pool (default, trap, quality, axis neighbours, six random draws)
picks the best config on each segment. Combined `V` is the size-weighted mix
of those segment values. Global `V*` is the best pool config on everyone.

C4 needs `(V_seg − V*) / (V* − V₀) ≥ 0.20`.

| seed | V* | V_seg | gap / headroom |
|---|---|---|---|
| 0 | 0.574 | 0.578 | 0.035 |
| 1 | 0.571 | 0.570 | −0.005 |
| 2 | 0.566 | 0.564 | −0.020 |
| **mean** | | | **0.004** |

Negative gaps are noise: a segment-best on a 80–user slice need not beat the
global winner on that slice after weighting.

## What this means

A global config is **not** a costly compromise across topics in this world.
Per-topic weights buy ~0 of the 0.10 headroom. That is Q4's check coming
back negative for this segmentation.

The headline benchmark stays **one global `w`**. Building M2/contextual RL
because "heterogeneity is sitting there" would be inventing a problem the
world does not have.

Not tried, on purpose: clustering on propensity or sensitivity after seeing
this result, then reporting whichever clustering passes. If someone later
wants a different segment definition, that is a new C4 with a new date.
